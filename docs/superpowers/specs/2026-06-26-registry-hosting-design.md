# Design: registry hosting + `@clube-bravos` namespacing

Date: 2026-06-26
Status: approved (design)
Sub-project: 3 of 4 (builds on sub-projects 1 & 2)
Repos: `clubebravos-design-system` (bulk), `code-adapter` (plugin emit string), `cbdigital_frontend` (proof)

## Goal

Host the Clube Bravos shadcn registry publicly on GitHub Pages and namespace it as `@clube-bravos`, so a
consumer configures one `registries` entry and runs `shadcn add @clube-bravos/<item>` with
`registryDependencies` resolving automatically — replacing the curl workaround used in the sub-project 1/2
proofs.

## Decisions (locked during brainstorming)

- **Access:** public static (components are brand UI, not secret; the manual is about visual consistency).
- **Host:** GitHub Pages, served from a `gh-pages` branch.
- **Publish trigger:** both — `push main` → `/r/` (latest); `push tag v*` → `/vX.Y.Z/r/` (pinned).
- **Approach A:** `peaceiris/actions-gh-pages@v4` with `keep_files: true` (the official `deploy-pages`
  does a full-site replace, which would wipe version dirs). State lives in the `gh-pages` branch; version
  dirs accumulate going forward.
- **Namespacing:** `@clube-bravos`. `build-registry` prefixes internal `registryDependencies`; item `name`
  fields stay bare; consumers map the namespace to the Pages URL in `components.json`.

## Constraints / facts

- GitHub repo: `ombrello-seguros/clube-bravos-design-system` → Pages base
  `https://ombrello-seguros.github.io/clube-bravos-design-system/`.
- `ci.yml` already triggers on push main, tags `v*`, and PRs (commitlint + lib build + npm publish on tag).
  The Pages workflow is SEPARATE (`registry-pages.yml`), a distinct concern.
- The registry artifacts (`public/r/*.json`, `public/figma-map.json`) are generated by
  `build:registry` / `build:figma-map` (sub-project 1/2) and committed.

## Architecture — four units

```
push main ─▶ CI build:registry ─▶ public/r/*.json ─▶ peaceiris (keep_files) ─▶ gh-pages /  ─▶ …/r/<item>.json (latest)
push vX.Y.Z ─▶ CI ───────────────────────────────▶ peaceiris (keep_files) ─▶ gh-pages /vX.Y.Z/ ─▶ …/vX.Y.Z/r/<item>.json
consumer components.json: registries["@clube-bravos"] = "https://…/r/{name}.json"
   shadcn add @clube-bravos/bravos-wizard-footer ─▶ resolves @clube-bravos/bravos-button + @clube-bravos/clube-bravos-theme
```

1. **Namespaced registryDependencies** — `scripts/build-registry.ts` prefixes each `registryDependency`
   that names one of our items with `@clube-bravos/`; external deps (future) stay bare. Regenerates
   `public/r/*.json`. (design-system)
2. **Pages workflow** — `.github/workflows/registry-pages.yml`: one job, triggers main + tag `v*`; builds
   the registry, stages `_site/{r, figma-map.json}`, deploys via peaceiris with `keep_files: true`,
   `destination_dir` = `vX.Y.Z` on a tag else root. Needs `permissions: contents: write`. (design-system)
3. **Consumer config + docs + plugin emit** — `guidelines/registry.md` documents the `registries` block +
   `shadcn add @clube-bravos/…` (latest and pinned); the plugin's `emit` install string becomes
   `npx shadcn add @clube-bravos/<registryItem>`. (design-system + code-adapter)
4. **Proof** — local namespace resolution: serve `public/`, a `components.json` with
   `registries:{"@clube-bravos":"http://localhost:4000/r/{name}.json"}`, run
   `shadcn add @clube-bravos/bravos-wizard-footer`, confirm it resolves deps via the namespace with no
   curl. The live Pages URL is a post-merge manual check.

## Namespacing detail

In `build-registry.ts`:
```ts
const itemNames = new Set(manifest.items.map(i => i.name));
const ns = (d: string) => itemNames.has(d) ? `@clube-bravos/${d}` : d;
// apply ns() to each entry's registryDependencies before writing public/r/<name>.json
```
Served result — `bravos-wizard-footer.json`:
`"registryDependencies": ["@clube-bravos/bravos-button", "@clube-bravos/clube-bravos-theme"]`.
The `name` field stays bare (`bravos-button`); the URL `{name}` template maps
`@clube-bravos/bravos-button` → `…/r/bravos-button.json`.

Consumer `components.json`:
```json
{ "registries": { "@clube-bravos": "https://ombrello-seguros.github.io/clube-bravos-design-system/r/{name}.json" } }
```
Then `npx shadcn add @clube-bravos/bravos-wizard-footer`. Pinned: point the registry value at
`…/vX.Y.Z/r/{name}.json`.

## Pages workflow detail

`.github/workflows/registry-pages.yml`:
```yaml
name: Registry Pages
on:
  push:
    branches: [main]
    tags: ['v*']
permissions:
  contents: write
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci --no-audit --no-fund
        env: { HUSKY: 0 }
      - run: npm run build:tokens && npm run build:registry && npm run build:figma-map
      - name: Stage site
        run: mkdir -p _site/r && cp public/r/*.json _site/r/ && cp public/figma-map.json _site/
      - id: dest
        run: echo "dir=${{ startsWith(github.ref,'refs/tags/') && github.ref_name || '' }}" >> "$GITHUB_OUTPUT"
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./_site
          destination_dir: ${{ steps.dest.outputs.dir }}
          keep_files: true
```

**Manual prerequisite (one-time, not automatable):** in the repo Settings → Pages, set the source to the
`gh-pages` branch (created by the first workflow run). Until then the URLs 404.

## Verification

- **Automated:**
  - design-system: `tests/registry.test.ts` extended — served items have `@clube-bravos/`-prefixed
    `registryDependencies`; the integrity check strips the prefix before validating each dep names a real item.
  - code-adapter: `tests/adapter.test.ts` extended — `emit` install === `npx shadcn add @clube-bravos/bravos-button`.
  - Local namespace proof: serve `public/`, a throwaway `components.json` with the localhost `registries`
    entry, `npx shadcn add @clube-bravos/bravos-wizard-footer` resolves all three items with no curl.
  - Site staging: run the `Stage site` commands locally, confirm `_site/r/*.json` + `_site/figma-map.json`.
- **Manual (post-merge):** enable Pages on `gh-pages`; `…/r/clube-bravos-theme.json` → 200; after a `v*`
  tag, `…/vX.Y.Z/r/…` → 200; a live `shadcn add @clube-bravos/…` against the Pages URL.

## Out of scope

- Private/authenticated registry; other hosts (Cloudflare/Vercel).
- npm→registry migration; the npm package keeps publishing as-is.
- Broader component coverage; the `code-adapter` variant-set resolution follow-up (sub-project 2).
- Pruning old version dirs from `gh-pages` (they accumulate; revisit if it ever matters).

## Assumption to verify (before the proof)

Namespaced `registries` in `components.json` (the `@clube-bravos` → URL mapping that makes
`shadcn add @clube-bravos/<item>` and prefixed `registryDependencies` resolve) requires a recent enough
shadcn CLI. The implementer MUST confirm the installed `shadcn` version supports the `registries` config
(consult the shadcn skill / docs) before the local namespace proof. If the available CLI predates it,
either pin/upgrade the CLI for the proof or fall back to full-URL `registryDependencies` and record the
deviation. A wrong assumption here makes the namespace proof fail — verify it first.
